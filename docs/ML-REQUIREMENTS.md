# Требования к ML-сервису (для ИИ-ассистента, который пишет код)

**Версия:** 2.1, 04.10.2026. **Словарь:** `dict-v2.1`. **Утверждено:** медэксперт и капитан команды — Вита.

Документ самодостаточный: здесь всё, что нужно, чтобы написать и проверить ML-сервис. Медицинские правила взяты из утверждённых материалов команды, их нельзя менять или «улучшать» в коде. Если что-то в протоколе не укладывается в эти правила, правильное поведение одно: вернуть находку с `uncertain: true` или флагом, а не придумывать своё правило.

**Материалы, на которые ссылается документ:**

| Файл | Что это | Как использовать |
|---|---|---|
| `findings-dictionary.yaml` (`dict-v2.1`) | Словарь: 48 кодов находок, синонимы, атрибуты, правила извлечения, ловушки, флаги | Единственный источник кодов и правил извлечения. Читать в рантайме, не хардкодить |
| `CHANGELOG-dict-v2.md` | Что изменилось с `dict-v1-ml` | Если уже есть код на v1, по этому файлу понять, что переделать |

| `synthetic-gold.json` | Эталонный ответ ML по каждому синтетическому протоколу в формате контракта | Прямой расчёт строгого F1 (раздел 9.4) |

## 1. Задача и граница ответственности

Система маршрутизации пациентов СМ-Клиники работает так: протокол УЗИ → находки → маршрут пациента к нужному врачу в нужный срок.

**ML извлекает факты, а бэкенд принимает решения.** Это ключевой принцип архитектуры, его рекомендуют организаторы кейса.

| ML (этот сервис) | Бэкенд (не делать в ML) |
|---|---|
| Получает файл протокола и метаданные от МИС | Хранит пациентов, протоколы, находки |
| Извлекает текст из .docx / .pdf | Применяет пороги и правила (`rules` в словаре) |
| Находит раздел «Заключение» | Решает: маршрут или нет, к кому, в какой срок, экстренно ли |
| Находит находки, цитату-доказательство и атрибуты | Ставит флаги `SYSTEM_UNKNOWN`, `SYSTEM_CONVERTED`, `DUPLICATE`, `MINOR` |
| Распознаёт отрицания, нормы, состояния после операции | Эскалация, уведомления, журнал, дашборд |
| Ставит флаги качества протокола (раздел 6) | Показывает всё врачу на подтверждение |

Из этого следует:

- ML **никогда** не присылает вердикт вроде «хирургический», «направить к хирургу» или «экстренно». Он присылает только `code`, `attributes`, `evidence` и `flags`.
- ML **возвращает факты даже ниже порога**: полип ЖП 3 мм, узел TI-RADS 2, BI-RADS 2, «фолликулярную кисту», обычные наботовы кисты. Отсеивает их бэкенд. Если ML отрежет такую находку сам, пропадёт объяснимость («почему маршрут не создан»). Физиологические состояния, которые находкой не являются (жёлтое тело без слова «киста», BI-RADS 1), идут в `notTriggered` с причиной `NORMAL`. Полное правило — раздел 4.3.
- Поля словаря `level`, `rules`, `targetSpecialty`, `targetDays`, `routeTemplateCode`, `ifMissing`, а также блоки `backend` и `routeTemplates` ML **игнорирует**.

## 2. Как ML встроен в систему

```
МИС (на демо — эмулятор) ──файл протокола + метаданные──▶ ML
ML ──результат: пациент, протокол, находки, флаги──▶ бэкенд  POST /api/integration/ml/results
```

- Бэкенд в ML не обращается. ML сам получает файл и сам отправляет результат.
- Стек: Python + FastAPI, порт **8000**.
- Адрес бэкенда задаётся переменной окружения `BACKEND_URL`: локально `http://localhost:8080`, в Docker `http://backend:8080`.
- Папка сервиса в репозитории — `ml/`. Нужен `Dockerfile`, блок `ml` в `docker-compose.yml` уже заготовлен (закомментирован).
- Данные (`data/raw/`) и большие файлы моделей в Git не коммитить.

## 3. Вход: что присылает МИС

На демо вместо МИС работает эмулятор: он берёт файл из архива, добавляет выдуманные метаданные и отправляет в ML. Блоки `patient` и `protocol` ML пересылает бэкенду **без изменений**.

```json
{
  "eventId": "evt-001",
  "eventType": "PROTOCOL_SIGNED",
  "patient": { "externalId": "mis-456", "fullName": "Соколова Анна Сергеевна", "lastName": "Соколова", "firstName": "Анна", "middleName": "Сергеевна", "birthDate": "1999-03-15", "sex": "F" },
  "protocol": { "externalId": "proto-789", "version": 1, "studyType": "PELVIS_FEMALE", "studyDate": "2026-09-07" },
  "fileName": "1 Ж ОМТ (23).docx",
  "contentBase64": "..."
}
```

| `eventType` | Что делает ML |
|---|---|
| `PROTOCOL_SIGNED` | Обрабатывает файл, отправляет результат со `status: DONE` (или `FAILED`) |
| `PROTOCOL_CORRECTED` | То же; `protocol.version` больше прежней, новый `resultId` |
| `PROTOCOL_ANNULLED` | Файл не обрабатывает, отправляет `status: ANNULLED` с `patient` и `protocol` |

`studyType` принимает значения `PELVIS_FEMALE`, `ABDOMEN`, `BREAST`, `THYROID`, `PROSTATE`, `LOWER_LIMB_VESSELS`, `KIDNEY`, `SOFT_TISSUE`. По нему ML сужает набор кандидатов: у каждого кода в словаре есть `studyTypes`.

Данные пациента ML **не извлекает из текста**: ФИО в протоколах пустое, возраст и пол бэкенд берёт из метаданных.

ФИО приходит от МИС **по частям** (`lastName`, `firstName`, необязательное `middleName`) и строкой `fullName`. ML пересылает весь блок `patient` без изменений, новые поля проверять не нужно. Если МИС прислала только `fullName`, части восстановит бэкенд.

## 4. Выход: как передавать результат

ML вызывает `POST {BACKEND_URL}/api/integration/ml/results` с заголовком `Content-Type: application/json`. **Один протокол — одно сообщение.**

| Ответ бэкенда | Что значит | Что делать ML |
|---|---|---|
| `202 Accepted` | Принято (или уже было принято раньше) | Ничего |
| `400 Bad Request` | Не хватает обязательного поля, неверный формат или неизвестный код находки; в теле указано, что не так | Залогировать, исправить, отправить заново |
| `5xx` / нет ответа | Бэкенд недоступен | Повторить через 5, 30, 120 секунд **с тем же `resultId`** |

Повторная отправка безопасна: бэкенд узнаёт сообщение по `resultId` и дубль не создаёт.

### 4.1. Пример сообщения

Пример: УЗИ малого таза. Полип эндометрия есть в заключении. Миома отрицается. Свободная жидкость со сгустками описана только в описательной части, в заключение не вынесена.

```json
{
  "resultId": "4f1c2a9e-8b7d-4e21-9a55-0c3d6e7f8a10",
  "status": "DONE",
  "modelVersion": "ml-1.0+dict-v2.1",
  "dictionaryVersion": "dict-v2.1",
  "processedAt": "2026-10-04T13:15:02+03:00",

  "patient":  { "externalId": "mis-456", "fullName": "Соколова Анна Сергеевна", "lastName": "Соколова", "firstName": "Анна", "middleName": "Сергеевна", "birthDate": "1999-03-15", "sex": "F" },
  "protocol": { "externalId": "proto-789", "version": 1, "studyType": "PELVIS_FEMALE", "studyDate": "2026-09-07" },

  "text": "УЛЬТРАЗВУКОВОЕ ИССЛЕДОВАНИЕ ОРГАНОВ МАЛОГО ТАЗА ...",
  "conclusion": "УЗ-признаки полипа эндометрия. Свободная жидкость в малом тазу.",
  "conclusionFound": true,

  "flags": [],

  "findings": [
    {
      "code": "ENDOMETRIAL_POLYP",
      "evidence": { "text": "УЗ-признаки полипа эндометрия", "start": 1840, "end": 1869 },
      "attributes": { "sizeMm": 8, "uncertain": false },
      "confidence": 0.93,
      "flags": []
    },
    {
      "code": "FREE_FLUID",
      "evidence": { "text": "неоднородная жидкость с эхогенными сгустками, общим объёмом около 200 мл", "start": 1502, "end": 1574 },
      "attributes": { "echogenic": "со сгустками", "volumeMl": 200, "beyondPelvis": true, "location": "боковой канал", "uncertain": false },
      "confidence": 0.88,
      "flags": [ { "code": "DISCREPANCY", "note": "в заключении только «свободная жидкость», в описании — сгустки и жидкость в боковом канале" } ]
    }
  ],

  "notTriggered": [
    { "code": "UTERINE_FIBROID", "evidence": { "text": "миоматозных узлов не выявлено" }, "reason": "NEGATION" }
  ],

  "error": null
}
```

### 4.2. Поля сообщения

Поля с пометкой «да» обязательны: если их нет, бэкенд ответит `400`.

| Поле | Обязательно | Тип | Описание |
|---|---|---|---|
| `resultId` | да | string | Уникальный ID сообщения, рекомендуется UUID. При повторе отправлять тот же |
| `status` | да | `DONE` / `FAILED` / `ANNULLED` | Итог обработки (раздел 5) |
| `modelVersion` | да | string | Версия модели / правил, для журнала и объяснимости |
| `dictionaryVersion` | нет (желательно) | string | Версия словаря, с которой работал ML (`dict-v2.1`). **Новое в v2** |
| `processedAt` | да | datetime ISO 8601 | Когда ML закончил обработку |
| `patient` | да | object | Из входа, без изменений |
| `protocol` | да | object | Из входа, без изменений |
| `text` | нет (желательно) | string | Полный извлечённый текст. Если он есть, фронт подсвечивает цитату прямо в протоколе |
| `conclusion` | при `DONE` | string | Текст заключения; пустая строка, если не найдено |
| `conclusionFound` | при `DONE` | boolean | Нашёлся ли раздел «Заключение» |
| `flags` | при `DONE` | array | Флаги уровня протокола, пустой массив, если флагов нет. **Новое в v2** (раздел 6) |
| `findings` | при `DONE` | array | Найденные находки; пустой массив, если находок нет |
| `notTriggered` | нет (желательно) | array | Что рассматривалось, но отброшено, и почему |
| `error` | при `FAILED` | object | `{ "code": "UNREADABLE_FILE", "message": "..." }` |

**Элемент `findings`:**

| Поле | Обязательно | Тип | Описание |
|---|---|---|---|
| `code` | да | string | Код из словаря, строго как в словаре. Неизвестный код → `400` |
| `evidence.text` | да | string | Дословная цитата из протокола, на которой основана находка |
| `evidence.start`, `evidence.end` | если передан `text` | integer | Позиции цитаты в `text` (символы, с 0, `end` не включительно) |
| `attributes` | нет | object | Извлечённые значения. Список атрибутов для каждого кода — `attributes` в словаре, как их извлекать — `extraction`. Атрибут, которого нет в тексте, **не передавать** (не `null`, не `0`) |
| `confidence` | нет | number 0–1 | Уверенность модели |
| `flags` | нет | array | Флаги этой находки. **Новое в v2** (раздел 6) |

**Элемент `notTriggered`:**

| Поле | Обязательно | Тип | Описание |
|---|---|---|---|
| `code` | да | string | Код из словаря |
| `evidence.text` | да | string | Цитата |
| `reason` | да | enum | `NEGATION` (отрицание), `NORMAL` (норма или физиологическое состояние, например жёлтое тело 25 мм), `POST_SURGERY` (состояние после операции) |

Причину `BELOW_THRESHOLD` («ниже порога») ML не использует: её ставит бэкенд.

**Элемент `flags`** (одинаковый у протокола и у находки):

```json
{ "code": "DISCREPANCY", "note": "необязательное пояснение для врача" }
```

### 4.3. Что куда возвращать (единое правило)

Это правило одинаково для требований, словаря (блок `ml.returnPolicy`) и разметки (колонка «Ответ ML» в Excel, `synthetic-gold.json`).

| Куда | Когда | Примеры |
|---|---|---|
| `findings` | В тексте **утверждается** то, для чего есть код, независимо от порога, размера и категории | полип ЖП 3 мм; узел TI-RADS 2 8,5 мм; гемангиома 8 мм; «фолликулярная киста» (`functional: true`); обычные наботовы кисты (`CERVICAL_RETENTION_CYSTS`); BI-RADS 2, импланты Br2; «небольшой выпот» (`FREE_FLUID`); тонкий эндометрий «не по дню цикла» (`thin: true`); грыжа «без признаков ущемления» (`incarcerated: false`); объём яичника ≥ 10 см³ на фоне КОК (`PCOM`, `onCOC: true`) |
| `notTriggered`, `NEGATION` | Отрицается **сама находка** | «данных за тромбоз не получено»; «конкрементов не выявлено» |
| `notTriggered`, `NORMAL` | Названо физиологическое состояние, похожее на находку, но ею не являющееся | жёлтое тело или фолликул ≤ 3 см **без слова «киста»**; «O-RADS 1» без образования; BI-RADS 1 без других изменений; ВМС расположена правильно |
| `notTriggered`, `POST_SURGERY` | Орган удалён, находка прооперирована | состояние после холецистэктомии |
| никуда | Для этого нет кода (`ml.notFindings`) | перегиб ЖП, метеоризм, кальцинаты простаты, «диффузные изменения миометрия» без формулировки аденомиоза |

- **Отрицание признака не отменяет находку.** «Пупочная грыжа, без признаков ущемления» → `HERNIA` в `findings` с `incarcerated: false`.
- **Гранулярность.** Одна находка — это код, сторона или доля (`attributes.side`), локализация (`attributes.location`) и тип или категория (`figo`, `birads`, `orads`, `tirads`). Несколько образований с одинаковыми ключами — одна находка с `count` и `sizeMm` наибольшего. Камень холедоха и камни ЖП — две находки `GALLSTONES` с разной `location`. Узлы FIGO 0 и FIGO 4 — две находки `UTERINE_FIBROID`. BI-RADS справа 5 и слева 1 — находка справа плюс `notTriggered NORMAL` слева.
- **Несколько кодов в одном протоколе возвращаются все.** ДГПЖ и остаточная моча — это `BPH` и `BPH_URINARY_RETENTION`; острый холецистит с камнем — `ACUTE_CHOLECYSTITIS` и `GALLSTONES`.
- **Оценка.** F1 считается по `findings`. `notTriggered` проверяется только в ловушках и в строках разметки «Отрицание» и «Физиологическая норма»; в остальных случаях он желателен, но не оценивается.

## 5. Обязательные сценарии

ML отправляет сообщение **на каждый протокол**, даже если находок нет или файл не прочитался. Иначе пациент потеряется незаметно, а дашборд не посчитает воронку.

| Ситуация | `status` | Что заполнить | Что сделает бэкенд |
|---|---|---|---|
| Находки есть | `DONE` | `findings` с находками | Покажет пациента врачу во вкладке «Новые» |
| Норма, находок нет | `DONE` | `findings: []`, по возможности `notTriggered` | Учтёт исследование в статистике, маршрут не создаст |
| Нет раздела «Заключение» | `DONE` | `conclusionFound: false`, флаг `NO_CONCLUSION` у протокола, находки по описательной части | Пометит протокол «требует внимания» |
| Файл не прочитался | `FAILED` | `error` с кодом и текстом | Покажет протокол в инбоксе как требующий внимания |
| Протокол исправлен в МИС | `DONE` | Тот же `protocol.externalId`, `version` больше прежней, новый `resultId` | Пересчитает находки и обновит маршрут без дублей |
| Протокол аннулирован в МИС | `ANNULLED` | `patient`, `protocol` (без находок), новый `resultId` | Закроет маршрут и остановит уведомления |
| Повторная отправка | как в исходном | Тот же `resultId` | Ответит `202`, ничего не изменит |

## 6. Флаги, которые ставит ML

Полный список с описаниями — в блоке `flags` словаря. ML ставит **только** флаги с `setBy: ML`.

| Код | Уровень | Когда ставить |
|---|---|---|
| `DISCREPANCY` | находка (или протокол, если расхождение не привязано к находке) | Находка есть в описании, но не вынесена в заключение; заключение слабее описания; прилагательное противоречит цифрам («гемодинамически значимый» при 40%); категория врача явно противоречит описанию |
| `INCOMPLETE` | находка | Нет обязательного параметра: категории BI-RADS или TI-RADS, расстояния от тромба до соустья, толщины эндометрия в постменопаузе, источника рефлюкса при варикозе |
| `NO_CONCLUSION` | протокол | Нет раздела «Заключение» |
| `PREP_VIOLATED` | протокол | «Не натощак», «после еды» и т. п. Находки при этом считаются достоверными |
| `OUTDATED_TERM` | находка | Устаревший термин, например «эндоцервикоз» |
| `INCORRECT_TERM` | находка | Термин не применим к УЗИ, например «холестаз» (читать как сладж) |
| `TEMPLATE_NORM` | находка | Норма в шаблоне протокола расходится с КР, например вены таза «N до 7 мм» при пороге КР 5 мм |

Флаги `SYSTEM_UNKNOWN`, `SYSTEM_CONVERTED`, `DUPLICATE` и `MINOR` ставит бэкенд, ML их не присылает.

## 7. Словарь находок: как с ним работать

### 7.1. Загрузка

- Читать словарь в рантайме: из файла `backend/src/main/resources/dictionary/findings-dictionary.yaml` или из `GET {BACKEND_URL}/api/dictionary/findings`.
- **Коды, синонимы и правила извлечения не хардкодить.** Если в словарь добавят код, ML должен подхватить его хотя бы по синонимам, без правки кода.
- Учитывать только коды с `active: true`; в `dict-v2.1` активны все 48.
- Версию из поля `version` передавать в `dictionaryVersion`.

### 7.2. Какие поля словаря читает ML

| Поле / блок | Зачем |
|---|---|
| `findings[].code`, `name`, `studyTypes` | Кандидаты для данного типа исследования |
| `synonyms` (список или `certain` / `suspected`) | Формулировки. `suspected` → `uncertain: true` |
| `attributes` | Какие атрибуты извлекать для кода |
| `extraction` | Как извлекать атрибуты, и особые случаи |
| `notThis` | Ловушки: что похоже, но относится к другому коду или не является находкой |
| `clinicalNote` | Контекст, полезный для понимания |
| `ml.*` | Общие правила: где искать, отрицания, неуверенность, состояние после операции, рост, размеры, сторона, категории, контекст пациентки, не-находки |
| `flags` | Флаги с `setBy: ML` |

## 8. Правила извлечения: что важно сделать правильно

Это сводка самого важного. Полные правила — в словаре: блок `ml` и поля `extraction` / `notThis` у каждого кода.

### 8.1. Приоритет полноты для экстренных и срочных находок

Для кодов, которые могут быть экстренными или срочными, пропуск опаснее ложной тревоги: ложную находку врач отклонит при подтверждении, а пропущенная потеряет пациента. При сомнении такую находку нужно **вернуть с `uncertain: true`**, а не отбрасывать.

### 8.2. Где искать

1. Сначала раздел «Заключение»: по нему решается, есть ли находка.
2. Атрибуты (размер, FIGO, категорию, расстояние, объём) брать из описательной части, если их нет в заключении.
3. **Находка есть только в описании** (или в описании она серьёзнее, чем в заключении) → вернуть её по описанию и поставить флаг `DISCREPANCY`. Это требование медэксперта: протоколы проверяются целиком, а не только по заключению.
4. Заключения нет → искать по описанию, `conclusionFound: false`, флаг `NO_CONCLUSION`.
5. В одном протоколе может быть **несколько находок**, их нужно вернуть все. Находки по разным сторонам или долям возвращаются **отдельными элементами** с `side`.

### 8.3. Отрицания (`ml.negationCues`)

- Отрицание относится только к той фразе, в которой стоит. «Конкрементов не выявлено. В просвете сладж» означает, что камни → `notTriggered: NEGATION`, а сладж → находка `BILIARY_SLUDGE`.
- **Отрицание признака не отменяет находку.** «Паховая грыжа, признаков ущемления нет» → `HERNIA` с `incarcerated: false`, а не `NEGATION`. Так же работают «кровоток сохранён» у яичника (это отрицание перекрута) и «глубокие вены проходимы» при тромбофлебите (это отрицание ТГВ, а тромбофлебит остаётся находкой).
- Отрицание экстренной находки проверять строго: «данных за тромбоз не получено» → `notTriggered: NEGATION` для `DEEP_VEIN_THROMBOSIS`.

### 8.4. Неуверенность (`ml.uncertaintyCues`)

«?», «нельзя исключить», «вероятно», «возможно», «под вопросом», «подозрение на», «по типу» → `uncertain: true`. Находку при этом **всё равно возвращать**.

### 8.5. Типичные ловушки

| Ловушка | Правильно |
|---|---|
| Жёлтое тело или фолликул до 3 см без слова «киста» («образование яичника — жёлтое тело 25 мм») | `notTriggered`, `reason: NORMAL` для `OVARIAN_LESION`. Если написано «киста жёлтого тела» или «фолликулярная киста» — `findings`, `functional: true` |
| Обычные наботовы (ретенционные) кисты; «эндоцервикоз» | `findings`: `CERVICAL_RETENTION_CYSTS` (для «эндоцервикоза» плюс флаг `OUTDATED_TERM`) |
| BI-RADS 1 по стороне | `notTriggered`, `reason: NORMAL` для `BREAST_LESION` с этой `side`; BI-RADS ≥ 2 — `findings` |
| «Небольшой выпот в малом тазу» | `findings`: `FREE_FLUID` с `amount: небольшое` (физиологический выпот отсекает бэкенд) |
| Узкая полоска жидкости у ЖП при остром холецистите | Атрибут `pericholecysticFluid: true` у `ACUTE_CHOLECYSTITIS`, **не** `FREE_FLUID` |
| Неполная компрессия вены и пристеночные массы при полной реканализации, «свежих тромботических масс нет» | `POST_THROMBOTIC_CHANGES`, **не** `DEEP_VEIN_THROMBOSIS` |
| Пристеночный тромб в аневризме артерии | `UNRECOGNIZED_ABNORMALITY` (аневризма), **не** тромбоз вен |
| «Состояние после холецистэктомии», «конкрементов в протоке не выявлено» | `notTriggered`, `reason: POST_SURGERY` для `GALLSTONES` |
| «Код МКБ: N80.0» | МКБ здесь классификатор болезней, а не мочекаменная болезнь |
| Тромбоз БПВ, МПВ или притоков | `SUPERFICIAL_THROMBOPHLEBITIS`, не `DEEP_VEIN_THROMBOSIS`. Если есть и то и другое, вернуть обе находки |
| «Перепад скорости кровотока не картируется» | Значимого стеноза нет, это **не** окклюзия |
| Диапазон «40–50%», «до 6–8 мм» | Верхняя граница: 50, 8 |
| Опечатки («холидох») | Распознавать как правильное слово |
| «TI-RADS 4b» без названия системы | Это система Kwak: `tiradsRaw: "4b"`, `tiradsSystem: KWAK`, `tirads: 5` |
| FIGO 3 | Интрамуральный узел, **не** субмукозный |
| Сладж вместе с камнями | Атрибут `sludge: true` у `GALLSTONES`, отдельную находку `BILIARY_SLUDGE` не возвращать |
| Холестероз, описанный как несмещаемые образования без тени | Вести как `GALLBLADDER_POLYP` (по размеру) |
| «Холестаз» в протоколе УЗИ | `BILIARY_SLUDGE` + флаг `INCORRECT_TERM` |
| Отклонение в заключении, которого нет ни в одном коде и нет в `ml.notFindings` (например, аневризма) | `UNRECOGNIZED_ABNORMALITY`, в `attributes.text` — фраза из заключения |
| Всё из `ml.notFindings` (мультифолликулярные яичники без критериев, перегиб ЖП, метеоризм, кальцинаты простаты и т. п.) | Не возвращать как находку |

### 8.6. Атрибуты

- **Размеры** (`ml.sizeParsing`): берётся наибольший размер в мм; см переводятся в мм; при нескольких образованиях — размер наибольшего плюс `count`.
- **Сторона** (`ml.sideCues`): `left` / `right` / `both`.
- **Категории** (`ml.categoryParsing`): BI-RADS → `birads` и `biradsSub`; O-RADS → `orads`; TI-RADS → `tirads` по шкале EU, плюс `tiradsRaw` и `tiradsSystem`. Категорию врача **не пересчитывать** по описанию; явное противоречие → `DISCREPANCY`.
- **Контекст пациентки** (`ml.patientContext`): `menopause`, `cycleDay`, `monthsSinceLmp`, `bleeding`, `hcgPositive`. Передаётся в атрибуты тех кодов, у которых они есть в `attributes`.
- **Расчётные значения:** объём яичника, если он не указан, считать по формуле 0,523 × длина × ширина × толщина (см) и ставить `volumeCalculated: true`. Размер матки в неделях **не** пересчитывать из миллиметров.
- Атрибут, которого нет в тексте, не передавать. Бэкенд различает «нет данных» и «значение»: это влияет на маршрут.

### 9.3. Отложенные протоколы — не использовать при настройке

Это имитация защиты: жюри будет проверять систему на новых протоколах. Отложенные протоколы нельзя использовать для подбора правил, промптов или обучения, только для итоговой проверки:

- ОМТ: 4, 7, 11, 14, 17, 19, 22, 25
- ЖП / ОБП: 2, 6, 9, 10, 14, 18, 21, 25
- Молочная железа: 2, 7, 9
- Простата: 3, 6, 9
- Щитовидная железа: 2, 5, 9

### 9.4. Метрики

Считать **четыре набора отдельно**: настроечные реальные, отложенные реальные, синтетика, итог.

| Метрика | Как считать |
|---|---|
| Precision / recall по каждому коду | Совпадение = тот же протокол + тот же `code` + та же `attributes.side` и `attributes.location` (если есть в эталоне). Для синтетики — по `synthetic-gold.json`, допустимые элементы не считаются ни TP, ни FP |
| Recall экстренных и срочных | Отдельной строкой. Цель — **не пропустить ни одной** на синтетике и отложенных |
| Ловушки и отрицания | По строкам «Отрицание» и «Физиологическая норма» и по `mustNotFind` в эталоне: код не должен попасть в `findings`; обязательные `notTriggered` должны совпасть по `code` и `reason` |
| Точность атрибутов | Доля совпавших ключевых атрибутов: размер, сторона, категория, `figo`, `incarcerated`, `obstruction`, `distanceToJunctionMm` и т. п. |
| Флаг `DISCREPANCY` | Recall по строкам, где «Где найдена» = описание |
| Время обработки | Среднее и максимальное на один протокол |

## 10. Нефункциональные требования

- Python + FastAPI, порт 8000, `Dockerfile`, переменная `BACKEND_URL`.
- Форматы файлов: `.docx` обязательно, `.pdf` желательно. Если файл не читается, отправить `status: FAILED` и `error.code: UNREADABLE_FILE`.
- Логировать каждый протокол: `resultId`, `protocol.externalId`, `version`, найденные коды, время обработки, ответ бэкенда.
- Повторы при `5xx` — через 5, 30, 120 секунд с тем же `resultId`.
- `modelVersion` меняется при каждом изменении модели, правил или промптов.
- Персональные данные из входа никуда, кроме бэкенда, не отправлять. Реальные протоколы не публиковать.
