# ML v8: повторная оценка на новых типовых текстах

05.10.2026, неизменная `dict-v2.1-extractor-8`.

На 96 новых синтетических протоколах строгий micro-F1 полной находки — **77,30%**.
С исправлением одной обнаруженной ошибки собственной разметки — **78,53%**.
Прежние 91,67% на 40 сложных текстах на этом новом наборе не воспроизвелись.
Модель между этими оценками не дорабатывалась: это различие выборок и разметки,
а не установленная регрессия исходного кода.

## Набор и процедура

По 12 протоколов на каждый из восьми типов УЗИ: 9 положительных и 3 отрицательных.
Всего 72 положительных, 24 отрицательных документа, 81 эталонная находка,
286 атрибутов, 29 из 48 активных кодов. Представлены обычные описания узлов,
кист, камней, миом, ДГПЖ, сосудистых изменений и грыж; часть протоколов содержит
две находки. Это сбалансированная авторская инженерная выборка, не распределение
реальных обращений и не полное покрытие справочника.

Все тексты вымышлены и составлены ассистентом. Тексты и ответы зафиксированы
до первого анализа, после проверки схемы. Среди 512 уникальных прежних текстов
не найдено совпадений даже после удаления чисел, пробелов и пунктуации.
Проверка новизны не доказывает независимость шаблонов и клиническую репрезентативность.

Каждый текст преобразован в DOCX и обработан через `process_event` с валидацией
выходного контракта. Девять вариантов оформления дали 864 прогона, но **96 уникальных
случаев**. Перед запуском сохранены хеши всех Python-файлов `ml/app`, словаря и эталона;
после оценки подтверждено отсутствие изменений. Две копии YAML побайтово равны.
Ни исправлений извлекателя, ни подбора ответов по предсказаниям не выполнялось.

## Основные метрики исходного эталона

| Метрика, исходное оформление | Значение |
|---|---:|
| F1 полной находки | **77,30%** |
| Precision / Recall полной находки | 76,83% / 77,78% |
| TP / FP / FN полной находки | 63 / 19 / 18 |
| F1 кода со стороной/локализацией | **98,16%** |
| TP / FP / FN кода со стороной/локализацией | 80 / 2 / 1 |
| F1 только кода, с учётом количества находок | 99,39% |
| Совпавшие размеченные атрибуты | 261/286 — 91,26% |
| Отрицательные документы с ложной находкой | **1/24** |
| Ошибки обработки | 0/96 |

`F1 = 2 × TP / (2 × TP + FP + FN)`. Сопоставление находок один к одному.
При ошибке одного размеченного атрибута полная находка даёт FP и FN, даже если
её код найден верно. Дополнительные неразмеченные атрибуты не проверяются.
Метрика кода со стороной/локализацией использует `side` и `location`, если они
размечены; названия сосудов и размеры в неё не входят. Поэтому 98,16% нельзя
выдавать за качество полностью заполненной находки.

Независимый пересчёт методом динамического программирования совпал с основным
оценщиком для полной находки и кода со стороной/локализацией во всех девяти вариантах.

## Ошибка разметки и семантика отсутствующего false

В `typical-006` ожидалось `uncertain=false` для «Диффузные изменения по типу АИТ».
Это ошибка автора эталона: `ml.uncertaintyCues` явно содержит «по типу».
Предсказанное `uncertain=true` соответствует словарю. Исходный эталон не переписан;
поправка применяется только в отдельно обозначенном ретроспективном пересчёте.

| Вариант подсчёта, оригинал | TP / FP / FN | F1 |
|---|---|---:|
| Первый строгий подсчёт по замороженному эталону | 63 / 19 / 18 | 77,30% |
| Строгий подсчёт с исправлением `typical-006` | 64 / 18 / 17 | **78,53%** |
| Та же поправка и отсутствующий булев атрибут считается false | 67 / 15 / 14 | **82,21%** |

Последний вариант соответствует соглашению применения булевых правил backend,
но отличается от строгого сравнения JSON: оценщик требует явного присутствия
размеченного значения. Например, два ответа по камням желчного пузыря теряют
строгий балл только из-за отсутствия `uncertain=false`. Такие случаи нельзя
приравнивать к ошибочному распознаванию заболевания.

Ещё два размеченных `refluxSource` задают БПВ/МПВ по названной в тексте вене
с рефлюксом. YAML не фиксирует перечисление допустимых значений и не уточняет,
означает ли это поле саму вену или только источник на уровне соустья. Эти
метки оставлены в первом подсчёте, но требуют согласования схемы. Не все 18
первоначальных несовпадений полной находки следует считать клиническими ошибками.

## Разбор несовпадений

| Протоколы | Расхождение в исходном оформлении |
|---|---|
| 006 | Ошибка разметки `uncertain`, рассмотрена выше |
| 025, 033 | У камней желчного пузыря отсутствует `uncertain=false`; размеры и локализация верны |
| 026 | У камней желчного пузыря не извлечено «несколько» в `count`, также отсутствует `uncertain=false` |
| 037, 043 | Не перенесён размер из описания к полипу эндометрия и эндометриоидной кисте |
| 041 | Для явно названного аденомиоза возвращено `uncertain=true` вместо ожидаемого false |
| 045 | У полипа цервикального канала пропущено `vascularized=true` при описанном кровотоке |
| 050, 051 | Пропущено `obstruction=false` при отсутствии расширения ЧЛС/лоханки; в 051 также пропущено количество |
| 071 | **Ложная BPH_URINARY_RETENTION** при «Остаточная моча в пределах нормы» |
| 073, 074 | Пропущен размеченный `refluxSource` БПВ/МПВ; семантика этого поля требует уточнения |
| 075, 078 | Не извлечено название вены ПкВ |
| 079 | У тромбоза ствола БПВ пропущено `location=trunk`; вена и расстояние 80 мм извлечены |
| 080 | У эктазии БПВ пропущены название вены и диаметр 5,8 мм |
| 085, 087 | Не извлечён размер грыжевого дефекта 18 и 9 мм |

В оригинале несовпадения затрагивают 19 документов: 18 с положительными
находками и один отрицательный. На уровне только кодов найдены все 81 ожидаемые
находки, добавлена одна ложная. Основная практическая проблема — полнота атрибутов
и связывание описания с заключением, а также обработка отрицаний нормы.

В `wrap35` и `wrap55` дополнительно теряется категория BI-RADS 2 у правой
молочной железы в `typical-013`. Из-за привязки сопоставления атрибутов к категории
оценщик атрибутов снимает для этой находки сразу пять баллов; это не пять
отдельных потерь значений в JSON. Во всех оформлениях одна ложная находка
в 24 отрицательных документах, ошибок обработки нет.

Стандартный критерий оценщика — F1 ≥95% и отсутствие ложных находок в норме —
не пройден. Порог не изменялся. Качество >90% на новых типовых документах
этот прогон также не подтверждает, включая дополнительные варианты подсчёта.

## Проверки и воспроизведение

Пройдены 325 ML unit tests, 72 Maven/JUnit-теста и 31 интеграционный сценарий
через работающие ML/backend и отдельную PostgreSQL проекта `meditron-verification`
на портах 18001/18081/15433. Maven выполнен в локальном контейнере без сети,
исходники смонтированы только для чтения, результаты сохранены в `.local`.
Рабочая база проекта `meditron-final` не использовалась этими проверками.
Тесты подтверждают работоспособность реализации, но не заменяют F1 на новых данных.

- [Эталон, независимый пересчёт и команды](../ml/eval/typical-v8-20261005/README.md).
- [Машинные метрики, хеши и результаты проверок](ml-typical-v8-20261005.metrics.json).
- Подробные DOCX, предсказания, манифесты и логи: `.local/ml-typical-v8-20261005/`.

Ограничения: синтетические тексты и разметка одного автора, без независимой
врачебной проверки; частичное покрытие атрибутов и кодов; искусственные пропорции
типов исследований и нормы. Для оценки клинической точности нужен внешний
отложенный корпус с согласованной полной разметкой. Эти 96 текстов после данного
анализа пригодны для регрессий, но больше не являются новым независимым испытанием.
