# Расширение ML-справочника

Актуально для `dict-v2.1-extractor-6`. YAML/JSON остаётся источником кодов,
синонимов, допустимых исследований и возвращаемых атрибутов. Медицинские
`rules`, сроки, специалисты и `ifMissing` исполняются только backend.

## Новый код и синонимы

Добавьте запись в `findings`, укажите `code`, `name`, `studyTypes`, `synonyms`
и `attributes`. Новый код участвует в общем извлечении упоминаний, отрицаний,
предположений, стороны, размера и количества без изменения Python.
Синонимы можно передавать списком либо группами `certain` / `suspected`.
Новый код не обязан быть в перечне существующих 48 кодов.

Следующий пример вымышленный и предназначен для проверки интеграции:

```yaml
- code: CUSTOM_FOCUS
  name: Особый очаг
  studyTypes: [BREAST]
  synonyms:
    certain: [тестовый очаг]
    suspected: [возможный тестовый очаг]
  attributes: [sizeMm, side, count, uncertain, stiffnessKpa]
  attributeExtractors:
    stiffnessKpa:
      type: number
      labels: [жесткость, жёсткость]
      unit: кПа
```

Текст «Тестовый очаг слева 9 мм, жесткость 17,5 кПа» даст код
`CUSTOM_FOCUS`, `side: left`, `sizeMm: 9`, `uncertain: false` и
`stiffnessKpa: 17.5`. Неупомянутые значения не выдумываются.
Список `attributes` фильтрует результат и проверяется перед отправкой.

## Новые атрибуты без изменения кода

`attributeExtractors` поддерживает:

| type | Поля | Поведение |
|---|---|---|
| number | labels, необязательные unit и multiplier | Число после метки; десятичная запятая разрешена; множитель по умолчанию 1 |
| integer | labels, необязательные unit и multiplier | Как number, но дробное значение не возвращается |
| boolean | positive, negative | Списки явных фраз; отрицательная фраза имеет приоритет |
| string | labels | Текст после метки до ближайшего разделителя |

Метки — буквальный текст, не регулярные выражения и не выполняемый код.
Атрибут извлекается только в контексте найденной сущности; отсутствующие и
противоречивые значения остаются неизвестными. Для boolean следует задавать
оба набора формулировок. Для разных единиц с неоднозначным пересчётом нужна
отдельная проверяемая схема, а не угадывание единиц.

Пример дополнительного измерения в сантиметрах, которое передаётся в мм:

```yaml
attributeExtractors:
  depthMm:
    type: number
    labels: [глубина]
    unit: см
    multiplier: 10
```

Добавьте `depthMm` в `attributes`. Для такого поля валидатор также проверит тип.

## Повторное использование анатомической обработки

Если новый код соответствует уже поддерживаемому способу извлечения, задайте
`extractionProfile`, например `THYROID_NODULE`, `BREAST_LESION`,
`UTERINE_FIBROID`, `OVARIAN_LESION`, `GALLSTONES` или `BPH_URINARY_RETENTION`.
Доступны профили существующих 21 кодов; точный перечень — `app/extensions.py`.
Поле `attributes` обязательно. Профиль подключает специализированные
синонимы и обработку атрибутов; наружу всегда возвращается ваш `code`.
Поэтому профиль следует выбирать по смыслу, а не просто ради получения размера.

Без профиля работает общий извлекатель. Описание совершенно нового сложного
медицинского признака свободным текстом само по себе не создаёт алгоритм:
для новых связей между органами, новой шкалы или сложной логики потребуется
адаптер и синтетические проверки. Поля `extraction` и `notThis` в исходном
справочнике являются текстовыми требованиями; произвольные новые предложения
в них не исполняются автоматически.

## Обновление и проверки

- Backend может отдавать эти поля через GET `/api/dictionary/findings`.
  Данные GET имеют приоритет; ML не добавляет отсутствующие в GET коды.
- При локальном YAML перезапустите сервис после изменения файла.
  Изменение содержимого словаря отражается в хеше `modelVersion` результата.
- Уже сохранённое событие не пересчитывается. Для нового анализа используйте
  новое событие МИС; исправление протокола — также новую версию протокола.
- Для нового кода проверьте положительный случай, отрицание, предположение,
  историю, несколько находок и отсутствующие атрибуты. Не оценивайте качество
  по результатам, автоматически записанным той же моделью как эталон.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_fact_extraction_v5.py -v
```

Эти проверки включают новый код в существующем справочнике, обновление
синонимов, новый числовой атрибут, профиль под другим кодом, загрузку из GET,
отрицания и полный путь синтетического DOCX до проверенного JSON.

В v2.1 записи active:false исключаются из результата. Для будущих версий
полный корневой блок ml.returnPolicy сохраняет выбор нового профиля обработки.
Это не интерпретатор произвольных медицинских инструкций: сложные изменения
свободного текста extraction/notThis требуют реализации и проверки.
