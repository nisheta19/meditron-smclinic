# Устойчивость извлечения ML v7 — 04.10.2026

Последующий тест на **ещё 96 новых синтетических документах** дал F1 полной находки
**73,81%** при неизменной v7. Он обнаружил не покрытые приведёнными ниже примерами
ошибки. См. [отдельную новую оценку](ml-v7-new-evaluation.md). Результаты ниже
сохранены как история предыдущего прогона.

Версия: `dict-v2.1-extractor-7`. Модель остаётся локальным извлекателем по справочнику.
Обучения нейросети и сетевой передачи документов нет. Медицинский YAML не изменён;
копии backend и ML совпадают побайтно.

## Почему проседал F1

Аудит из `C:/hackaton/.local/ml-audit-20261004` воспроизведён на исходной v6.
Главная причина — физическая строка DOCX считалась законченной единицей смысла.
Перенос разрывал отрицание, размер, название органа или словосочетание. Поэтому
одинаковый текст с другим оформлением давал F1 около 61% вместо исходного результата.
Другие причины: не все варианты заголовков исключали анамнез, размер «17 на 9 мм»
читался как 9 мм, окончания слов и уточнения органа мешали связать отрицание с находкой.

В v7 восстановление продолжений выполняется до извлечения фактов. Границы разделов,
анатомических полей и отдельных утверждений сохраняются. Нельзя просто склеить
весь документ: отрицательная фраза тогда может отменить следующую положительную.
Отдельно проверены заглавные буквы вместе с переносами, размеры в мм/см, объёмы,
сторона, предположение после запятой, отсутствие ущемления и флотации.
Цитаты и смещения по-прежнему указывают на неизменённый `fullText`.

## Результаты и порядок проверки

F1 полной находки означает совпадение кода и **всех размеченных атрибутов**.
Сопоставление один к одному; лишние находки учитываются как FP, пропуски — FN.
Неверный атрибут даёт и FP, и FN. Дополнительные неразмеченные атрибуты не оцениваются.
Эталоны не менялись после просмотра предсказаний.

| Набор | Документов | F1 v6 | F1 v7 / последнее измерение |
|---|---:|---:|---:|
| Новые примеры из предоставленного аудита | 35 | 88,89% | 100% |
| Прежние реальные DOCX с переносами | 89 | 61,54% | 90,79% |
| Прежние синтетические DOCX с переносами | 33 | 61,05% | 98,95% |
| Первая новая синтетическая выборка, затем использована для исправлений | 64 | 52,53% | 100% |
| Вторая новая выборка: **первый прогон**, до исправлений по ней | 72 | 63,87% | **98,25%** |
| Та же вторая выборка после исправлений | 72 | 63,87% | 100% |
| Прежние реальные DOCX, исходный вид | 89 | 90,79% | 90,79% |
| Прежние синтетические DOCX, исходный вид | 33 | 98,95% | 98,95% |

64 первых примера были записаны до начала исправлений, но после первого запуска
с результатом 74,47% стали набором для поиска ошибок. Затем написаны ещё 72 примера,
по 9 на каждый из восьми типов исследований. Они включают норму, анамнез, несколько
находок, двусторонние находки, категории, размеры и отрицательные атрибуты.
Первый результат этой второй выборки: **TP 56, FP 2, FN 0**, precision 96,55%,
recall 100%, F1 98,25%. Совпали 125/125 размеченных атрибутов. Лишними оказались
две находки в отрицательных фразах: уточнение паховой области и окончание слова
в формулировке гиперплазии. Общие правила отрицания исправлены; обе ошибки теперь
зафиксированы в регрессионных тестах.

Первый результат второй выборки показывает перенос на ещё не проверявшиеся примеры.
Повторные 100% — уже регрессионная оценка. Все эти новые тексты и эталоны написаны
ассистентом; это **не независимая разметка врача и не внешний клинический тест**.
Нельзя переносить 98–100% на любые новые реальные протоколы без их проверки.

## Проверки оформления и нормальных случаев

Для 136 новых текстов проверены девять вариантов: исходный, переносы через 35 и
55 символов, заглавные буквы, заглавные буквы с переносами, неразрывные пробелы,
десятичная точка, знак умножения, варианты заголовков. Это 1 224 DOCX-прогона,
**а не 1 224 независимых документа**. В финальном прогоне все размеченные находки
совпали. В каждой версии первой выборки 18 отрицательных документов, второй — 21;
ложных находок в них нет, ошибок обработки нет.

На исходной синтетике 33 документа после перевода в верхний регистр строгий F1
равен 96,84%: один из оставшихся штрафов связан с буквальным полем `text` у
`UNRECOGNIZED_ABNORMALITY` — оно верно повторяет верхний регистр источника, тогда
как неизменённый эталон хранит обычный регистр. Основной оценщик не подменялся
нормализованным сравнением ради более высокого числа.

## Что осталось в прежнем эталоне

На 89 реальных документах остаются TP 143, FP 23, FN 6. Шесть расхождений атрибутов
и 17 дополнительных фактов перечислены в [отчёте v2.1](ml-v21-review.md).
Например, в эталоне для размера 22×23 указан 22, а извлекатель возвращает максимум 23;
размер из правой молочной железы не переносится в левую ради совпадения с разметкой.
Они остаются штрафами в основном расчёте, отдельный «исправленный эталон» не создавался.

## Воспроизведение

Из `C:/hackaton/final/ml`:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m app.generalization --gold tests/fixtures/generalization-validation.json --output ../.local/generalization-validation
.\.venv\Scripts\python.exe -m app.generalization --gold tests/fixtures/generalization-development.json --output ../.local/generalization-development
```

В выходной папке — сформированные DOCX, JSON предсказаний, несовпадения и метрики
по каждому варианту. Код выхода ненулевой при F1 ниже 95%, ошибке обработки или
любой ложной находке в отрицательном документе. Можно передать `--variants original`
для быстрого прогона. Новые тесты добавляются отдельным JSON с ожидаемыми ответами,
заданными **до** первого обращения к извлекателю.

SHA-256 первой и второй выборок соответственно:

```text

bf897b1870cea8b24d519ac3aaa3ddd4e9ca9169cb096721c68ea3defc0e1fb9
```

Словарь: `e8a4a9dc163b4f68956f190db7acf59706e0d4777aed3312eb4a795ed3aee66b`.
Реальные протоколы и подробные результаты остаются в игнорируемой `.local/`.
Публичные фикстуры содержат только вымышленные тексты, без данных пациентов.

## Расширение и интеграция

Новые коды и синонимы продолжают загружаться из YAML, простые атрибуты — через
`attributeExtractors`. Есть проверка нового кода, размера через перенос и нового
числового атрибута. Свободное медицинское описание в YAML не исполняется как программа;
для нового сложного признака нужны профиль и примеры. [Правила расширения](ml-dictionary-extensions.md).

Пройдены 312 ML unit tests, Maven-тесты бэкенда и 17 сквозных сценариев на отдельной
PostgreSQL: backend → DOCX → ML → JSON callback → backend, исправления, аннулирование,
отрицательные сценарии, сортировки и авторизация. Проверка охватывает 19 API backend
и 4 API ML. Сохранённые результаты старых событий не пересчитываются автоматически;
v7 применяется к новым событиям. Повторная доставка старого результата не запускает
анализ заново — для пересчёта передайте исправленную версию протокола с новым eventId.
