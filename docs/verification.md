## Исправления при интеграции

- Добавлена отправка DOCX и событий из backend в ML с ожиданием отдельного callback.
- Полный справочник отдаётся со всеми общими правилами и версией; краткий формат сохранён.
- Результаты проверяются до сохранения: обязательные поля по статусу, словарь,
  studyType, атрибуты, флаги, confidence и цитаты. Учтены Unicode code points.
- Повтор resultId с другим содержимым возвращает 409. Одновременная повторная
  доставка не создаёт дублей. Уникальность версии закреплена в PostgreSQL.
- Старый callback/аннулирование не изменяет более новую версию или данные пациента.
  Аннулирование более новой версии создаёт запись, блокирующую поздний старый результат.
- Запрещена перепривязка одного externalId протокола к другому пациенту.
- Неверные параметры пагинации возвращают 400; большое число страницы не переполняется.
- Изменение врачом атрибутов/кода пересчитывает направление; неактивные протоколы
  и находки нельзя повторно подтвердить или исправить.
- Экстренная непроверенная находка предыдущего независимого исследования остаётся
  видимой в истории и учитывается в срочности инбокса.
- 10 демонстрационных JSON приведены к текущему формату и проверены приёмом backend.
- В Compose подключён ML, добавлены проверки готовности и постоянный SQLite-том.
- Зафиксированы зависимости, добавлены воспроизводимые скрипты и актуальные OpenAPI.

NLP-исходники ML и медицинский YAML побайтово совпадают с исходной текущей моделью.
Клинические пороги в ходе интеграции не менялись.

## Проверка сбоев

`tests/resilience.py` запускает собственные Java/ML-процессы на отдельных портах.
Без ML backend возвращает 502; повтор того же события после запуска ML успешен.
Затем тест отключает backend, отправляет аннулирование в ML, фиксирует неудачную
доставку и перезапускает ML. Очередь и resultId сохраняются. После запуска backend
результат автоматически доставлен с третьей попытки; пациент и протокол не дублируются.
Тест завершает только созданные им процессы.

## Границы результата

- Проверка 89/89 означает успешное извлечение, доставку и сохранение, а не F1=100%.
  Оценка точности v6 отдельно описана в [ML README](../ml/README.md).
- В архиве нет frontend-приложения; проверить UI невозможно по этим исходникам.
- Методы исполнения маршрутов/уведомлений из проектного `openapi.yaml` пока
  не реализованы. `routes=[]` и `routeId=null` — состояние исходного прототипа.
- В словаре BI-RADS ≥ 5 получает срок 3 дня и наследуемый уровень PLANNED.
  Это зафиксировано тестом как поведение YAML; клиническое изменение уровня требует
  следующей согласованной версии справочника.
- Приём результатов сериализуется транзакционной блокировкой; нагрузочные испытания
  большого клинического потока не проводились. Авторизации в исходном backend нет.
- Запуск Docker-контейнеров здесь не подтверждён. Проверены Compose и локальные процессы.
