# Новая карточка пациента — подключение и проверка

05.10.2026. Подготовленная вёрстка из `deliverables/patient-card` перенесена
в `frontend/src/components/patient-card/`. Исходный пакет не изменён.
Карточка доступна по прежнему адресу `/#/patients/{id}`. Затем применены три
уточнённых макета: проверка протокола, сводка пациента и окно уведомления.
Три пункта бокового меню сохранены. На широких экранах весь интерфейс увеличивается
пропорционально от основы 1280 px; при 1920 px масштаб равен 150%.

## Подключение

- ФИО и данные пациента: `GET /api/patients/{id}`. Неизвестные контакты,
  рост, вес и группа крови остаются прочерками; данные макета не используются.
- Открытые маршруты: `clinicalRoutes`. Специалист, тип, этап, крайний срок
  `dueAt`, запись и просрочка берутся из backend. Раскрытие строки показывает
  находки маршрута, историю этапов, тактику и задачи. Закрытые маршруты
  доступны через историю справа.
- Уведомления: `GET /api/patients/{id}/notifications`. Показаны фактические
  `sentAt`, `readAt`, `bookedAfter`. Нажатие на текст открывает сообщение
  целиком и статус доставки. Отсутствие прочтения не заменяется датой отправки.
- Кнопка отправки использует ручные шаблоны из `/api/notification-templates`
  и `POST /api/routes/{id}/notifications`. Точный текст до отправки получает
  `GET /api/routes/{id}/notification-preview?templateCode=...`, использующий
  тот же серверный рендерер, что и отправка. Предпросмотр не сохраняет сообщение,
  не меняет этап и не создаёт таймеры. `409 CONFIRM_REQUIRED` требует
  отдельного нажатия «Отправить повторно». Смена шаблона или маршрута сбрасывает
  подтверждение. Ошибки API отображаются, кнопка защищена от двойного нажатия.
- Карточка и сообщения обновляются раз в 15 секунд, пока вкладка видима.
  Ошибка загрузки уведомлений показывается с повтором, без подстановки демо.
- Находка или исследование в истории открывают отдельный экран протокола: текст, цитаты,
  подтверждение/отклонение и добавление/удаление находки. Заменённая версия
  не редактируется; независимый старый протокол доступен. Находка без протокола
  открывается отдельным окном. Флаги качества и предупреждение о незавершённом
  маршруте доступны в «Подробнее».
- «Сохранить и отправить уведомление» подтверждает ожидающие находки выбранного
  протокола, обновляет маршруты и открывает окно с предпросмотром. Непосредственная
  отправка требует отдельного нажатия. Для экстренного случая отправка недоступна.
  Выбор срочности и ручные изменения маршрута в макете — отключённые заглушки:
  эти значения по-прежнему рассчитывает backend.
- Cookie-сессия и CSRF сохранены. Этапы маршрута приходят от МИС;
  неподдерживаемых запросов ручного редактирования `steps` новая карточка не делает.

Реальной доставки push/SMS нет: backend сохраняет сообщение в локальной CRM-заглушке.
Показ прочтения и записи проверен входящими событиями CRM и МИС. Расписание также
остаётся серверной заглушкой. В явном автономном `?mock=1` реальная рассылка отключена.

## Визуальная проверка

При CSS-размере 1280 × 1625, DPR 2, основные размеры и координаты на одинаковых
вымышленных данных совпали с исходным макетом:

| Блок | X / Y | Ширина × высота |
|---|---|---|
| Поиск | 212 / 25 | 1052 × 64 |
| Белая карточка | 212 / 169 | 1052 × 1431 |
| Первая строка маршрута | 225 / 498 | 739 × 78 |
| Раскрытый маршрут | 225 / 661 | 739 × 231 |
| Первое уведомление | 225 / 1074 | 739 × 79 |
| Отправка | 227 / 1252 | 200 × 48 |
| Первая находка | 225 / 1395 | 739 × 52 |

В новых макетах также проверены экран протокола и окно уведомления:

| Блок | X / Y | Ширина × высота |
|---|---|---|
| Карточка с протоколом | 212 / 169 | 1052 × 1504 |
| Текст протокола | 228 / 485 | 739 × 478 |
| Сохранить и отправить | 228 / 1589 | около 288 × 48 |
| Окно уведомления | 330 / 466 | 621 × 600 |

Координаты проверяются на содержимом макета с допуском 2 px.
Боковое меню не копирует устаревшую «Картотеку» с изображения:
в действующем приложении сохранены согласованные «Дашборд», «Входящие», «Находки».
Скриншоты просмотрены, совпадение не заявляется побитовым: остаются различия
растеризации текста. На живых данных число строк зависит от ответа backend;
длинный текст переносится, полное уведомление открывается нажатием.
На 390, 768, 1024, 1280 и 1920 px проверено отсутствие переполнения страницы;
на узком экране широкие таблицы прокручиваются внутри секций.

пациента и без отправки уведомления, ошибок браузера и HTTP нет.

## Повторение

Из корня проекта:

```powershell
docker compose -p meditron-verification -f docker-compose.yml -f compose.verification.yaml up --build -d --wait
.\ml\.venv\Scripts\python.exe tests/integration.py --report .local/patient-card-integration.json
.\ml\.venv\Scripts\python.exe tests/frontend_fixtures.py
cd frontend
$env:FRONTEND_URL='http://127.0.0.1:13000'
$env:BROWSER_CHANNEL='msedge'
npm test
node tests/e2e.mjs
node tests/patient-card-live.mjs
node tests/design.mjs
node tests/dashboard.mjs
node tests/filters.mjs
node tests/auth-browser.mjs
node tests/auth-live.mjs
```

Перед повторным запуском сценариев с мутациями снова создайте `frontend_fixtures.py`.
Они не предназначены для рабочего порта 3000. `patient-card-smoke.mjs`, напротив,
только читает рабочую карточку; по умолчанию использует 3000.

Для точной геометрии запустите Vite и `node tests/patient-card-visual.mjs`,
затем `node tests/three-layouts-visual.mjs`
с `FRONTEND_URL=http://127.0.0.1:5173`. Файл `tests/patient-card-visual.html`
содержит исключительно тестовый макет и не входит в production-сборку.
Локальные отчёты и снимки: `.local/patient-card/`, `.local/frontend-e2e.json`,
`.local/design-results.json`, `.local/patient-card-integration.json`,
`.local/patient-card-ml-tests.log`, `.local/patient-card-maven.log`.
Последний прогон: `.local/three-layouts/`, `.local/three-layouts-integration.json`,
`.local/three-layouts-ml.log`, `.local/three-layouts-maven.log`.
