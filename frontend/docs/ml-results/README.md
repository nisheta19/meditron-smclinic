# Демо-данные: сообщения ML

Файлы в формате `MlResult` из `openapi.yaml`, то есть ровно то, что сервис распознавания отправляет
в `POST /api/integration/ml/results`. Фронтенд в демо-режиме прогоняет их через ту же логику, что описана
для backend. Backend может использовать их для своих тестов как есть.

| Файл | Что внутри |
|---|---|
| `samples.json` | 7 протоколов из выданных примеров (ОМТ, вены и артерии нижних конечностей, щитовидная железа). Текст сохранён, ФИО вымышленные |
| `demo.json` | 17 синтетических сообщений, только для демо: полип эндометрия, ЖКБ, полипы ЖП выше и ниже порога, BI-RADS 2 и 4, грыжа, гидронефроз, ДГПЖ, экстренный тромбоз, нераспознанный файл (`FAILED`), протокол без заключения, исправленная версия протокола (v1 → v2), аннулирование |
| `demo-queue.json` | 3 сообщения, которые «поступают» по кнопке в демо-режиме: BI-RADS 5, субмукозная миома, аневризма аорты |

Синтетика помечена префиксом `ml-demo-` в `resultId` и не должна попадать в метрики качества распознавания.

## Как добавить свой пример

Добавьте объект `MlResult` в `demo.json`. Поля `evidence.start/end` можно не указывать:
мок найдёт цитату в `text` сам. Находки ниже порога словаря (`conditions`) автоматически
уйдут в `notTriggered` с причиной `BELOW_THRESHOLD`, а коды, которых нет в словаре, получат `OUT_OF_SCOPE`.

Что происходило с пациентом после поступления протокола (подтверждение, маршрут, уведомления, запись),
задаётся в `src/api/mock/seed.js` → `SCENARIOS`.
