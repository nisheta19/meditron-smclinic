# Интерфейс MEDITRON

React 19 + Vite 7. Рабочий режим обращается к настоящему backend: входящие,
картотека, фильтры и поиск, карточка пациента, текст и цитаты, версии протокола,
подтверждение, отклонение, добавление и удаление находок, просмотр справочника.
Списки на открытой вкладке обновляются каждые 5 секунд, сохраняя поиск, фильтры
и номер страницы. Поступивший через ML результат появляется автоматически.

## Запуск всей системы

Из корня проекта:

```powershell
docker compose up --build -d --wait --wait-timeout 180
```

Интерфейс: http://127.0.0.1:3000 . Nginx отдаёт сборку и передаёт `/api/` в
`backend:8080`. Рабочая цепочка: DOCX → backend → ML → callback → PostgreSQL → UI.
Frontend не обращается к ML напрямую. Все четыре сервиса запускаются общим Compose.
Адрес документации реализованного API: http://127.0.0.1:3000/open-api .

`FRONTEND_PORT` в корневой `.env` меняет внешний порт. Настройки Vite применяются
при сборке; переменная окружения уже запущенного nginx их не меняет.

## Разработка без frontend-контейнера

Нужен Node.js 22.12+ и работающий backend.

```powershell
cd frontend
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Открыть http://localhost:5173 . В `.env.local`:

- `VITE_USE_MOCK=false` — настоящий API, значение по умолчанию.
- `VITE_API_URL=/` — запросы через общий адрес и dev proxy.
- `API_PROXY=http://localhost:8080` — backend Docker. Для `Start-Local.ps1` использовать `http://127.0.0.1:18080`.
- `VITE_DOCTOR_NAME=Демо-врач` — подпись действий для локальной демонстрации; не авторизация.

`npm run build` собирает приложение, `npm run preview` только показывает сборку:
для API используйте nginx либо задайте доступный адрес backend с настроенным CORS.

## Что пока отсутствует в backend

Авторизации нет. Backend вычисляет специалиста, срок и срочность из YAML,
но не реализует запись, исполнение маршрутов и уведомления. UI показывает реальные
направления у находок и не создаёт для них вымышленные даты, шаги или просрочки.
Справочник в рабочем режиме доступен только для чтения. При добавлении находки
форма берёт разрешённые атрибуты из полного YAML, включая числовой BI-RADS.

Макеты списка и карточки воспроизведены по двум предоставленным CSS-экспортам
и изображениям. Inter и Manrope включены в сборку и загружаются с нашего сервера.
Недоступные функции сохранены визуально: фильтры «Просрочена запись» / «Без записи»,
дашборд и кнопки маршрута отключены. Счётчики этих двух фильтров показывают 0
как заглушку, а не результат расчёта записей. Неизвестные этап, прогресс, уведомления
и контактные/антропометрические значения обозначены прочерками.
В колонке срока показан рекомендуемый интервал backend, а не вымышленная дата записи.
Чекбоксы списка выбирают строки локально; массовой записи или рассылки нет.
Поля «Дата исследования с/по» открывают календарь при фокусе или нажатии в любом
месте поля. Можно одновременно вводить дату в формате дд.мм.гггг и выбирать её
в календаре: после выбора он остаётся открыт. Enter открывает календарь,
стрелка вниз переводит фокус на дни, стрелки перемещают выбор. Escape или
нажатие вне поля/календаря закрывает его, сохраняя дату и незавершённый ввод.
Закрытие панели также сохраняет ввод; «Сбросить фильтры» очищает его.
В API отправляются только корректные даты YYYY-MM-DD; неполный ввод не заменяет
последний применённый фильтр, пустое поле снимает его. Иконки календаря нет.
У всех полей фильтров серая обводка 1 px без зелёного ореола; выпадающие меню
и календарь используют серое выделение.
Основные экраны не показывают дополнительные бейджи срочности/статуса,
цветные боковые полосы, счётчики находок и служебные панели.
Флаги протокола и причины исключения фактов находятся в «Подробнее».
Версию/исследование можно выбрать через историю справа; рядом с заголовком
протокола показана только дата. Аватар использует фрагмент предоставленного
макета списка; данные и выводы протоколов в изображение не встраиваются.

## Отдельная автономная демонстрация

Только явный `?mock=1` или `VITE_USE_MOCK=true` включает старую демонстрацию
маршрутов на вымышленных данных. Она имеет собственные условные правила,
не отправляет изменения в backend и не подходит для оценки качества ML.
`npm run static` собирает её в `dist/sm-route.html`. Ошибка сети в рабочем режиме
никогда не переключает интерфейс на заглушку. Реальные тексты из архивного
`samples.json` удалены; исходный ZIP не изменён.

## Проверки

```powershell
cd frontend
npm ci
npm test
npm run build
npx playwright install chromium
cd ..
.\ml\.venv\Scripts\python.exe -X utf8 tests/frontend_fixtures.py
cd frontend
npm run test:e2e
npm run test:design
node tests/filters.mjs
```

Требуются работающий Docker-проект и демонстрационная БД. Подготовка создаёт новые
вымышленные DOCX и проводит их через nginx, backend и ML. Перед повторным E2E
запуском повторите `frontend_fixtures.py`: тесты подтверждают и отклоняют находки.
Для установленного Edge вместо скачивания Chromium можно задать
`$env:BROWSER_CHANNEL='msedge'`. `UI_FIXTURES` задаёт путь к JSON подготовленных
тестовых записей; `FRONTEND_URL` — адрес интерфейса. Результаты и снимки — в `.local/`.

`test:design` отдельно проверяет размеры двух макетов при ширине 1280 px,
выбор строк, отключённые заглушки, цитаты и адаптивность при 390/768/1024/1280/1920 px.
Отдельно проверяется отсутствие украшений и подписей вне макета для срочных,
подтверждённых, отклонённых, ручных и помеченных флагами находок.
В этом тесте ответы API подменяются полностью вымышленными данными из
`tests/design-fixtures.mjs`, БД не меняется. Снимки `.local/design-list.png` и
`.local/design-patient.png` предназначены для визуального сравнения.
Реальные запросы и сохранение изменений проверяет `test:e2e`.
`node tests/filters.mjs` проверяет ручной ввод, сохранение даты/черновика, фокус календаря,
переходы месяцев, границы дат для API, сброс, серые состояния и нулевые счётчики.
Он использует вымышленные ответы API, БД не меняется. Отчёт и снимки:
`.local/filter-controls-results.json`, `.local/filter-controls*.png`.

Структура: `src/api` — HTTP и отдельное демо; `src/pages` — экраны;
`src/components` — формы и компоненты; `src/lib/evidence.js` — Unicode-цитаты;
`src/lib/findingFields.js` — поля YAML; `tests` — модульные и браузерные проверки.

Обзор интеграции: [отчёт](../docs/frontend-review.md).
